# System Settings: Notifications (Deprecated)

**Note:** The dedicated UI for managing notifications has been deprecated in the current application structure. Notification preferences are now handled within individual modules where applicable.

This document describes the intended functionality of the previously planned Notifications section.

---

The **Notifications** section allows users to fine-tune how and when they receive alerts from the application, ensuring they stay informed without being overwhelmed.

## Key Features

### 1. Email
- **Purpose**: To manage notifications sent to the user's email address.
- **Functionality**: Provides granular control over which events trigger an email notification, such as direct mentions, task assignments, or system alerts. Users can choose to receive emails instantly or as a daily/weekly digest.

### 2. In-App
- **Purpose**: To configure notifications that appear directly within the application interface.
- **Functionality**: Users can toggle on or off different types of in-app alerts and banners, managing real-time interruptions.

### 3. SMS
- **Purpose**: To manage urgent alerts sent via text message.
- **Functionality**: Allows users to opt-in to SMS notifications for critical events, such as security alerts or system-wide outages.
